This site itself. The name is older than the stack — these days it is a Next.js application, exported as a fully static site and served from Firebase Hosting.

Everything on the site is a file in the repository. Articles are MDX; the reading list is a small JSON database of every book with its status and progress, merged into year pages at build time; projects, podcasts, and the uses page follow the same pattern. There is no CMS and no server — publishing anything means a git push, and the deploy workflow does the rest.

That is a deliberate design position, not a limitation. Content as plain files means the whole site is greppable, versioned, and portable; static generation means it is fast everywhere and there is nothing to patch or babysit. The most dynamic thing on the site is the theme toggle — light, dark, or follow-the-system — which is handled client-side with CSS custom properties.

It is also where the writing lives, which makes it the one project here that all the others eventually link back to.
